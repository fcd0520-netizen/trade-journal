# AI振り返りの有効化

取引詳細の「AIで振り返る」から、1件だけを明示的な送信確認後に分析します。
通常の記録は引き続き端末保存です。生成結果も同じ取引の`aiReview`に保存し、JSONバックアップ・復元に含めます。

## 送信内容

- 銘柄、種別、取引日、方向、状態、結果、市場環境・テーマ・イベント、理由、感情、振り返り、ルール遵守の自己申告。
- 決済は直近3件の理由・感情・振り返り・損益の符号だけ。数量、価格、損益額、口座残高、他の取引は送信しません。
- 自由記入欄に含まれる個人情報は自動で除去できないため、送信前のプレビューで確認します。
- 取得結果は判断・ルール・次の一歩の3項目。最新相場の検索や売買推奨は行いません。

## 有効化前に行う設定

1. Vercelの対象チーム`trade-journal-takuma`、プロジェクト`trade-journal`を確認します。
2. AI Gatewayの利用資格・残高を確認し、このプロジェクトのOIDCリクエストに対する少額の予算上限を設定します。初期案は月$1です。自動チャージは不要です。課金設定は所有者が確認してください。
3. Firewallに`@vercel/firewall`条件を持つルールを作成します。Rate limit IDは`trade-journal-ai-review`、上限は5回/600秒、超過時は429にします。既存ルールは変更しません。ルールを確認してから所有者がPublishします。
4. 環境変数`AI_REVIEW_ENABLED=true`を設定して再デプロイします。初期値は未設定（停止）です。モデルは`openai/gpt-6-luna`に固定しています。モデルを変える場合はコードの`REVIEW_MODEL`とプレビューの送信先表示も確認してください。
5. VercelではOIDCを使用します。APIキーの配布やブラウザへの保存は不要です。外部の検証環境でキーを使う場合も、`AI_GATEWAY_API_KEY`はサーバー側だけに設定してください。

回数制限は全利用者で共有するバケットです。Vercel側のカウンターはリージョン単位なので厳密な世界全体の上限ではありません。月次予算も併用してください。予算はソフトキャップで、境界をまたぐ1リクエスト分は完了することがあります。

ルール未設定、回数確認失敗、資格情報なしの場合は生成を停止します。同一オリジン確認はブラウザからの誤送信対策であり、利用者認証ではありません。この公開APIを個人専用だとは扱わず、送信量・出力量制限、回数制限、予算で公開範囲に応じた費用を抑えます。

## 最小限の実機確認

1. 理由を入力したテスト記録を開き、送信確認にチェックするまで送信できないことを確認します。
2. 送信し、3項目のコメントを確認します。画面を開いただけではAIを呼び出しません。
3. 再読み込みして結果が残ること、記録を編集すると変更前のコメントと表示されることを確認します。
4. バックアップを書き出し、復元後もコメントが残ることを確認します。
5. 1回の実リクエストについてAI Gateway Logsでモデル、使用量、費用を確認します。公開前にテスト用のルールで超過時の429も確認します。

## 開発時の検証

`npm run test:ai`で、生成APIの拒否経路・上流エラーの非公開化・送信項目の制限・バックアップ互換性を検証します。モデルと回数制限はモックなので費用は発生しません。ローカル開発環境では回数制限SDKがバイパスされるため、生成も停止します。

SDK: AI SDK 7。公式資料: [AI Gateway OIDC](https://vercel.com/docs/ai-gateway/authentication-and-byok/oidc)、[回数制限SDK](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting-sdk)、[予算](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets)。
